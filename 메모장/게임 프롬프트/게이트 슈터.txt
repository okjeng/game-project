새로운 웹 게임을 하나 만들어줘.

게임 이름은 임시로 "게이트 슈터(Gate Shooter)"로 한다.

목표는 가족들이 함께 즐길 수 있는 가볍고 재미있는 하이퍼 캐주얼 스타일의 아케이드 슈팅 게임이다.

중요:
- 기존 프로젝트의 기술 스택과 구조를 먼저 확인한다.
- 기존 게임이나 사이트의 공통 UI/레이아웃/컴포넌트를 최대한 재사용한다.
- 기존 기능이나 API를 임의로 수정하거나 삭제하지 않는다.
- 게임을 새로 추가하는 방식으로 구현한다.
- 실제 구현 전에 현재 프로젝트 구조를 먼저 분석하고, 그 구조에 맞춰 작업한다.


━━━━━━━━━━━━━━━━━━━━━━
1. 게임 핵심 컨셉
━━━━━━━━━━━━━━━━━━━━━━

한 명의 귀여운 캐릭터가 장난감 총을 들고 앞으로 이동한다.

플레이어는 캐릭터를 좌우로 움직이며 몬스터를 장난감 총으로 공격한다.

게임 진행 중 여러 개의 게이트가 등장한다.

예:

+20
-10

x2
-20

+50
+10

플레이어는 어느 게이트를 통과할지 선택해야 한다.

게이트를 통과하면 현재 캐릭터 수 또는 공격력이 증가하거나 감소한다.

예:

현재 캐릭터 10명

→ +20 게이트 통과

→ 캐릭터 30명

또는

현재 캐릭터 30명

→ -10 게이트 통과

→ 캐릭터 20명

게임이 진행될수록 몬스터가 많아지고 난이도가 올라간다.

마지막에는 대규모 몬스터 웨이브 또는 보스 몬스터가 등장한다.

목표는 최대한 많은 몬스터를 처치하고 높은 점수를 얻는 것이다.


━━━━━━━━━━━━━━━━━━━━━━
2. 전체적인 게임 분위기
━━━━━━━━━━━━━━━━━━━━━━

절대로 현실적인 총기 게임처럼 만들지 않는다.

전체적인 분위기는:

- 밝고 귀여운 캐릭터
- 장난감 총
- 귀여운 몬스터
- 만화 스타일
- 캐주얼
- 가족 친화적
- 폭력적인 연출 최소화
- 피/혈흔/고어 표현 금지
- 총알 대신 장난감 탄환, 에너지탄, 물방울탄, 폼탄 등을 사용
- 몬스터가 공격받으면 쓰러지거나 "퐁!" 하고 사라지는 방식

게임을 보는 순간

"아이도 할 수 있는 재미있는 아케이드 게임"

이라는 느낌이 들어야 한다.


━━━━━━━━━━━━━━━━━━━━━━
3. 캐릭터 디자인
━━━━━━━━━━━━━━━━━━━━━━

플레이어 캐릭터는 귀엽고 단순한 3D 또는 2.5D 스타일의 캐릭터로 만든다.

예시:

- 둥근 머리
- 큰 눈
- 단순한 표정
- 작은 몸
- 귀여운 헬멧
- 캐주얼한 옷
- 장난감 총을 양손으로 들고 있음

캐릭터는 너무 특정 게임 캐릭터를 닮지 않도록 독창적으로 디자인한다.

장난감 총은:

- 플라스틱 장난감 느낌
- 둥글고 안전한 디자인
- 밝은 색상의 포인트
- 총구에서 에너지탄이나 폼탄이 발사되는 느낌

실제 총기처럼 사실적인 디자인을 사용하지 않는다.


━━━━━━━━━━━━━━━━━━━━━━
4. 몬스터 디자인
━━━━━━━━━━━━━━━━━━━━━━

몬스터도 무섭게 만들지 않는다.

예시:

- 젤리 몬스터
- 둥근 외계인
- 작은 로봇 몬스터
- 슬라임
- 눈이 큰 괴물
- 장난감 로봇

몬스터마다 간단한 특징을 준다.

예:

일반 몬스터
- 느림
- 체력 낮음

빠른 몬스터
- 빠르게 접근

큰 몬스터
- 체력 높음

방어 몬스터
- 여러 번 맞아야 사라짐

보스
- 크기가 크고 패턴이 단순함

몬스터가 공격받을 때 피가 나오면 안 된다.

대신:

"퐁!"

"팡!"

"펑!"

같은 만화식 효과와 함께 사라지게 한다.


━━━━━━━━━━━━━━━━━━━━━━
5. 게임 화면
━━━━━━━━━━━━━━━━━━━━━━

세로형 모바일 게임처럼 보이지만 PC에서도 마우스로 플레이할 수 있도록 만든다.

기본 화면:

┌─────────────────────────────┐
│ SCORE       WAVE       ❤️   │
│ 12,450       5         3    │
│                             │
│       👾      👾             │
│                             │
│   👾                         │
│                             │
│        🔫                   │
│                             │
│      +20       -10          │
│       🚪       🚪           │
│                             │
└─────────────────────────────┘

캐릭터는 화면 아래쪽에 위치하고,

몬스터는 위쪽에서 등장한다.

게임 진행에 따라 화면이 자연스럽게 앞으로 이동하는 러너 스타일의 느낌을 준다.


━━━━━━━━━━━━━━━━━━━━━━
6. 플레이어 조작
━━━━━━━━━━━━━━━━━━━━━━

PC:

- 마우스 좌우 이동
- 또는 A / D
- 또는 방향키 ← →

모바일:

- 화면을 터치한 상태에서 좌우 드래그

캐릭터가 좌우로 이동한다.

자동으로 앞으로 진행되며 플레이어는 이동 방향만 조절한다.

총은 기본적으로 자동 발사한다.

즉:

플레이어는
"이동 + 게이트 선택"

에 집중한다.

버튼을 계속 눌러 총을 쏘는 방식으로 만들지 않는다.


━━━━━━━━━━━━━━━━━━━━━━
7. 게이트 시스템
━━━━━━━━━━━━━━━━━━━━━━

게임의 가장 중요한 재미 요소다.

게임 진행 중 두 개 이상의 게이트가 등장한다.

예:

        +20          -10

        🚪           🚪

플레이어가 왼쪽으로 이동하면 +20 게이트를 통과한다.

오른쪽으로 이동하면 -10 게이트를 통과한다.

게이트를 통과할 때 즉시 결과를 보여준다.

예:

+20

"캐릭터 +20!"

캐릭터 수가 증가한다.

게이트 종류:

+10
+20
+30
+50

-5
-10
-20

x2

÷2

초기 버전에서는 너무 복잡하게 만들지 말고

+10
+20
-10
-20

정도부터 시작한다.

게임 밸런스를 잡은 후 x2, ÷2 등을 추가할 수 있도록 구조를 확장 가능하게 만든다.


━━━━━━━━━━━━━━━━━━━━━━
8. 캐릭터 수 시스템
━━━━━━━━━━━━━━━━━━━━━━

기본 캐릭터 수는 1명이다.

게이트를 통과하면서 캐릭터 수가 증가할 수 있다.

예:

1명
→ +20
→ 21명

21명
→ +10
→ 31명

31명
→ -20
→ 11명

캐릭터가 여러 명이 되면 뒤쪽에 따라오는 형태로 표현한다.

단, 캐릭터가 100명 이상이 되어도 브라우저 성능이 떨어지지 않도록 실제 캐릭터를 무한 생성하지 않는다.

필요하면 화면에는 일부 캐릭터만 표시하고 내부적으로는 숫자로 관리한다.

예:

실제 숫자: 127명

화면:

🔫 🔫 🔫 🔫 🔫 ...
+123명

또는 캐릭터들이 작은 그룹 형태로 표현되도록 한다.


━━━━━━━━━━━━━━━━━━━━━━
9. 슈팅 시스템
━━━━━━━━━━━━━━━━━━━━━━

플레이어 캐릭터 또는 캐릭터 그룹은 자동으로 몬스터를 공격한다.

장난감 총에서:

- 폼탄
- 에너지탄
- 물방울탄

등이 발사된다.

총알이 몬스터에 맞으면:

작은 이펙트
+
점수 증가
+
몬스터 제거

를 보여준다.

타격감은 재미있게 만든다.

예:

"POP!"

"+100"

"COMBO x3"

하지만 폭력적이거나 잔인한 연출은 사용하지 않는다.


━━━━━━━━━━━━━━━━━━━━━━
10. 콤보 시스템
━━━━━━━━━━━━━━━━━━━━━━

연속으로 몬스터를 처치하면 콤보가 올라간다.

예:

COMBO x2
COMBO x3
COMBO x5
COMBO x10

콤보가 높아질수록 점수 보너스를 준다.

화면에 큰 텍스트가 잠깐 나타났다 사라지는 방식으로 연출한다.


━━━━━━━━━━━━━━━━━━━━━━
11. 스테이지 진행
━━━━━━━━━━━━━━━━━━━━━━

게임은 여러 개의 Wave로 구성한다.

예:

WAVE 1
→ 일반 몬스터

WAVE 2
→ 일반 + 빠른 몬스터

WAVE 3
→ 일반 + 큰 몬스터

WAVE 4
→ 대규모 몬스터

WAVE 5
→ BOSS

처음부터 너무 어렵게 만들지 않는다.

게임을 시작하면 누구나 쉽게 플레이할 수 있어야 한다.

12. 보스전
━━━━━━━━━━━━━━━━━━━━━━

🤖 거대 장난감 로봇

예:

와 함께 점수를 보여준다.

14. 가족용 기능을 고려한 구조
━━━━━━━━━━━━━━━━━━━━━━

이 게임은 나중에 가족별 기록을 저장할 수 있도록 설계한다.

예:

🏆 가족 최고 기록

엄마 18,920
아빠 16,450
나 12,450

현재 구현에서는 실제 로그인/DB가 없다면 로컬 저장(localStorage)을 사용해도 된다.

다만 나중에 서버 저장 기능을 붙일 수 있도록 게임 결과 데이터를 다음처럼 분리해서 관리한다.

- score
- highScore
- monstersDefeated
- maxCombo
- wave
- gateChoices
- playTime

사이트 전체는 다크 네온 테마를 사용한다.

메인 사이트 디자인과 통일감을 유지한다.

배경:

Deep Charcoal
#18181B

포인트:

Neon Green
#2ECC71

Violet
#8E44AD

Coral
#FF6B6B

단, 게임 내부에서는 캐릭터와 몬스터가 더 잘 보이도록 밝고 다채로운 색을 적극적으로 사용한다.

18. 애니메이션
━━━━━━━━━━━━━━━━━━━━━━

게임의 재미를 위해 다음 애니메이션을 적극적으로 사용한다.

- 캐릭터 이동
- 총 발사
- 탄환 이동
- 몬스터 등장
- 몬스터 피격
- 몬스터 제거
- 게이트 등장
- 게이트 통과
- 숫자 증가/감소
- 점수 증가
- 콤보 표시
- 보스 등장
- 스테이지 클리어

단, 과도한 화면 흔들림이나 번쩍이는 효과는 피한다.


━━━━━━━━━━━━━━━━━━━━━━
19. 사운드
━━━━━━━━━━━━━━━━━━━━━━

가능하면 효과음을 구조적으로 추가할 수 있도록 만든다.

필요한 효과음:

- 게임 시작
- 총 발사
- 몬스터 피격
- 몬스터 제거
- 게이트 통과
- + 게이트
- - 게이트
- 콤보
- 보스 등장
- 보스 처치
- 게임 오버
- 최고 점수 갱신

브라우저 자동재생 정책을 고려해서 사용자가 게임 시작 버튼을 누른 후 사운드를 활성화한다.

사운드 파일이 아직 없다면 사운드 시스템 인터페이스만 먼저 만들어도 된다.


━━━━━━━━━━━━━━━━━━━━━━
20. 성능
━━━━━━━━━━━━━━━━━━━━━━

웹 브라우저에서 부드럽게 동작해야 한다.

중요:

- DOM 요소를 과도하게 생성하지 않는다.
- 캐릭터가 많아질 경우 실제 캐릭터 수만큼 DOM을 생성하지 않는다.
- 게임 루프는 requestAnimationFrame 기반으로 구성한다.
- 충돌 판정은 효율적으로 처리한다.
- 게임이 종료되면 animation frame과 event listener를 반드시 정리한다.
- 메모리 누수가 발생하지 않도록 한다.
- PC와 모바일 모두 대응한다.


━━━━━━━━━━━━━━━━━━━━━━
21. 게임 엔진 구현
━━━━━━━━━━━━━━━━━━━━━━

현재 프로젝트에 이미 게임 엔진 또는 Canvas 기반 구조가 있다면 먼저 확인하고 기존 구조를 최대한 활용한다.

없다면 이 게임은 Canvas 기반으로 구현하는 것을 우선 검토한다.

게임 상태를 명확하게 분리한다.

예:

START
PLAYING
GATE_CHOICE
BOSS
GAME_CLEAR
GAME_OVER
PAUSED

게임 데이터와 렌더링 로직을 분리한다.

게임 밸런스 값은 코드 곳곳에 하드코딩하지 말고 별도 설정 객체로 관리한다.

예:

GAME_CONFIG

- startingCharacters
- gateValues
- enemySpawnRate
- enemyHealth
- playerSpeed
- bulletSpeed
- bossHealth
- comboMultiplier


━━━━━━━━━━━━━━━━━━━━━━
22. 중요한 게임 플레이 원칙
━━━━━━━━━━━━━━━━━━━━━━

이 게임에서 가장 중요한 것은 "복잡한 게임"이 아니라 "계속 한 판 더 하고 싶은 게임"이다.

따라서:

- 첫 플레이는 10초 안에 이해할 수 있어야 한다.
- 조작은 매우 단순해야 한다.
- 게이트 선택은 직관적이어야 한다.
- 몬스터 처치 타격감은 확실해야 한다.
- 점수 상승이 눈에 보여야 한다.
- 난이도는 조금씩 증가해야 한다.
- 게임 한 판은 너무 길지 않게 한다.
- 게임 종료 후 바로 다시 플레이할 수 있어야 한다.


━━━━━━━━━━━━━━━━━━━━━━
23. 절대 하지 말아야 할 것
━━━━━━━━━━━━━━━━━━━━━━

- 현실적인 총기
- 피
- 혈흔
- 신체 훼손
- 잔인한 사망 연출
- 무서운 공포 몬스터
- 복잡한 RPG 시스템
- 복잡한 장비 시스템
- 복잡한 스킬 트리
- 과도한 광고
- 과도한 팝업
- 모바일 화면에서 작은 버튼
- 지나치게 긴 튜토리얼

가족들이 편하게 즐길 수 있는 게임이어야 한다.


━━━━━━━━━━━━━━━━━━━━━━
24. 개발 진행 방법
━━━━━━━━━━━━━━━━━━━━━━

먼저 현재 프로젝트를 분석한다.

1. 기술 스택 확인
2. 기존 게임 구조 확인
3. 공통 레이아웃 확인
4. 기존 UI 컴포넌트 확인
5. 라우팅 구조 확인
6. 게임을 추가할 적절한 위치 확인

그 다음 최소 플레이 가능한 버전(MVP)을 먼저 만든다.

MVP에는 반드시 다음이 포함되어야 한다.

- 게임 시작
- 캐릭터 이동
- 자동 사격
- 몬스터 등장
- 몬스터 처치
- 게이트 등장
- + 게이트
- - 게이트
- 캐릭터 수 증가/감소
- 점수
- 게임 오버
- 다시 플레이

MVP가 정상적으로 작동한 후:

1. 캐릭터 애니메이션
2. 몬스터 종류 추가
3. 콤보
4. Wave
5. 보스
6. 이펙트
7. 사운드
8. 최고 기록
9. 가족 기록 연동

순서로 확장한다.

한 번에 모든 기능을 억지로 구현하지 말고 단계적으로 개발한다.

각 단계가 끝날 때 실제 브라우저에서 게임을 실행하여 오류를 확인한다.

특히 게임이 "재미있게 플레이되는지"를 우선 확인한다.


━━━━━━━━━━━━━━━━━━━━━━
25. 최종 목표
━━━━━━━━━━━━━━━━━━━━━━

이 게임은 우리 가족 게임 사이트의 "슈팅/아케이드 대표 게임"이 된다.

현재 사이트의 첫 번째 게임은 "블록 블라스트"이고,

이 게임은 두 번째 또는 이후 추가되는 게임으로 들어간다.

사이트에서 사용자가 게임 카드를 클릭하면 이 게임으로 이동한다.

게임 내부에는 반드시 [메인으로 돌아가기] 기능을 제공한다.

최종적으로 다음과 같은 게임 사이트가 되는 것을 목표로 한다.

🧩 퍼즐
- 블록 블라스트

🕹️ 아케이드
- 게이트 슈터

🎲 캐주얼
- 앞으로 추가

게임이 하나씩 추가될수록 사이트의 게임 라이브러리가 자연스럽게 확장될 수 있는 구조로 개발한다.

먼저 현재 프로젝트 구조를 분석한 후,
구현 계획을 간단히 제시하고,
그 다음 실제 코드를 작성해라.
